# goemail documentation site

The source for <https://kartikrocks.github.io/goemail/>, built with
[Docusaurus](https://docusaurus.io/).

It lives on `main` alongside the code on purpose: a PR that changes
documented behaviour should change the docs in the same review. Docs on a
separate branch drift from the code they describe.

## Local development

```bash
npm ci
npm start        # http://localhost:3000/goemail/
```

`npm start` builds only the unreleased docs plus the newest version so
startup stays fast as versions accumulate. Use `npm run start:all` to
preview every live version.

## Before pushing

```bash
npm run check    # lint + typecheck + build
```

Individually:

| Command | Does |
| --- | --- |
| `npm run lint` | Biome lint + format check |
| `npm run lint:fix` | Biome autofix |
| `npm run typecheck` | `tsc` |
| `npm run build` | full production build, all live versions |
| `npm run build:fast` | narrowed build — what CI runs on PRs |

## Editing docs

Pages are Markdown in `docs/`, one file per topic. To add one:

1. Create `docs/<id>.md` with `id`, `title`, and `description` frontmatter.
2. Add the id to `sidebars.ts` under the right category.

The sidebar is explicit rather than autogenerated, so ordering is
deliberate and a new file cannot silently rearrange the nav.

**`docs/` is the unreleased version.** It tracks `main` and is served at
`/docs/next/`. The released docs readers land on live in
`versioned_docs/version-<minor>/`. See [VERSIONING.md](VERSIONING.md) before
cutting a release or fixing docs for an already-released version.

## Deployment

Pushing to `main` with changes under `website/` deploys via
`.github/workflows/docs.yml`. There is nothing to run by hand — do not
commit built output to a branch.
